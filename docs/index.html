The cleanup

The scan is the easy week.

Photogrammetry, LiDAR and aerial imagery will give you an accurate place. None of it gives you a game asset. Between the two sits the same list of jobs, on every asset.

  • Retopology Where the hours go

    The mesh arrives as dense triangle soup: millions of tris, no edge flow, non-manifold in places. Someone rebuilds it in quads, deciding one asset at a time which silhouette details matter.

  • UV layout

    Remeshing throws the UVs away. Messy topology gives you islands that won’t unwrap without distortion, and bake errors you can’t fix without starting the unwrap again.

  • De-lighting Where the hours go

    Every texture carries the sun and shadows of the day it was shot. Getting them out, so the asset holds up under your lighting, is still mostly done by hand.

  • Materials

    You get one flat colour map. Your engine wants albedo, roughness, normals and the rest.

Then LODs, collision, scale and pivots. Then the next asset.

There is a tool for each of these. Instant Meshes, ZRemesher, Quad Remesher, Unity’s De-Lighting Tool, the shadow passes in Metashape and RealityCapture. You have probably used most of them. The work is running all of them on every asset, knowing which one to reach for, and fixing what each one breaks.

People are still the only thing that runs that pipeline. We are building agents that can.

The plan

From 2D imagery to a place in your engine.

We can’t do this yet. This is the plan, stage by stage. Nothing below is shipped.

Agents do the work inside each stage, with the same tools you would use, and pick up new ones as they ship. Every hand-off between stages is a file with checks, so a failure stops where it started and you can see where every surface came from.

  1. Source

    a named location → licensed imagery, elevation, survey data

    A lot of free imagery forbids commercial use or 3D derived from it. Every file keeps its source and licence, so your legal team can trace any asset.

  2. Reconstruct

    imagery → georeferenced 3D reconstruction

    Improving fast, and the output is accurate and unusable: the triangle soup above.

  3. Segment

    reconstruction → buildings, ground, roads, vegetation, props

    Each class goes to a different method. A hangar, a kerb and a tree need different treatment.

  4. Infer the unseen

    top-down view → facades, heights, occluded geometry

    A satellite sees roofs, one lighting condition and no facades. We measure first and generate last, and every surface is tagged measured or inferred, so you always know which is which.

  5. Build the mesh

    segmented scene → meshes in Blender

    Per object: reconstruct it, place a library asset, or generate it procedurally.

  6. Optimise for play

    Where the hours go
    meshes → retopology, UVs, LOD chain, collision, to your budgets

    Built to your triangle and texture budgets, which differ by platform and genre.

  7. De-light and texture

    Where the hours go
    captured colour → true albedo → PBR materials

    True colour first. Full de-lighting can be checked: relight the result and compare it with a real capture.

  8. Compile

    assets → your engine, your formats, your conventions

Verify, at every hand-off

Each stage has to pass a check before the next one runs. Budgets, seams, scale and footprints are checked in code. Whether the place is right is checked against photos the pipeline never saw.
